# analyze-failures

A command-line tool for analyzing structured failure logs from the readlater article fetcher.

## Overview

This tool reads the structured JSON failure log (generated by the failure logging system) and produces various analytical reports to help identify patterns, prioritize improvements, and guide retry strategies.

## Building

```bash
cd backend/cmd/analyze-failures
go build -o analyze-failures .
```

## Usage

```bash
analyze-failures [flags]
```

### Flags

- `-log <path>`: Path to the failure log file (default: "fail.log")
- `-report <type>`: Type of report to generate (default: "summary")
  - `summary`: Overview of failures by category, domains, and strategies
  - `domain`: Per-domain failure analysis with category breakdown
  - `category`: Per-category analysis with top domains and strategies
  - `retry`: Recommendations for which URLs to retry with specific improvements
- `-since <time>`: Only analyze failures since this time (RFC3339 format, e.g., "2026-01-24T00:00:00Z")
- `-top <N>`: Number of top items to show in reports (default: 10)

## Report Types

### Summary Report

Provides a high-level overview of all failures:
- Total failure count and time range
- Breakdown by failure category with percentages
- Cloudflare mitigation rate
- Top N failing domains
- Strategy usage statistics

Example:
```bash
analyze-failures -report summary -top 10
```

### Domain Report

Analyzes failures grouped by domain:
- Per-domain failure counts
- Last failure timestamp
- Category breakdown for each domain
- Strategies attempted for each domain

Useful for identifying problematic domains that need special handling.

Example:
```bash
analyze-failures -report domain -top 20
```

### Category Report

Analyzes failures grouped by category:
- Per-category statistics and percentages
- Cloudflare mitigation rate per category
- Top domains for each category
- Strategy usage per category

Useful for understanding which types of failures are most common and which strategies work best for each type.

Example:
```bash
analyze-failures -report category
```

### Retry Report

Generates actionable retry recommendations:
- URLs that failed due to Cloudflare challenges (try FlareSolverr or headless browser)
- URLs that failed due to bot detection (try TLS fingerprinting or better headers)
- URLs that timed out (try simple retry or longer timeout)

Useful for creating retry queues after implementing new fetcher improvements.

Example:
```bash
analyze-failures -report retry
```

## Time Filtering

You can filter analysis to only include recent failures:

```bash
# Analyze only failures from the last 24 hours
analyze-failures -since "2026-01-24T12:00:00Z" -report summary

# Analyze failures from a specific date onwards
analyze-failures -since "2026-01-20T00:00:00Z" -report domain
```

## Integration with Import/Migrate Tools

The retry report output can be integrated with import/migrate tools to automatically retry failed articles after fetcher improvements are deployed:

1. Generate a retry list:
   ```bash
   analyze-failures -report retry > retry_recommendations.txt
   ```

2. Extract URLs and feed them back into the import pipeline:
   ```bash
   # Parse URLs from retry recommendations
   grep "^  - https://" retry_recommendations.txt | sed 's/^  - //' > urls_to_retry.txt

   # Import them again
   readlater import < urls_to_retry.txt
   ```

## Failure Categories

The tool recognizes the following failure categories:
- `cloudflare_challenge`: Cloudflare bot detection/challenge pages
- `bot_detection`: Other bot detection (403/429 without Cloudflare)
- `timeout`: Request timeouts or deadline exceeded
- `network_error`: Connection failures, DNS errors
- `http_error`: HTTP 4xx/5xx errors
- `content_extraction`: Failed to extract article content
- `redirect_loop`: Too many redirects
- `invalid_url`: URL parsing failures

## Example Workflow

1. Run the server/importer for a period to collect failures
2. Generate a summary to understand the overall situation:
   ```bash
   analyze-failures -report summary
   ```
3. Identify top failing domains:
   ```bash
   analyze-failures -report domain -top 20
   ```
4. Understand which categories are most problematic:
   ```bash
   analyze-failures -report category
   ```
5. After implementing improvements (e.g., FlareSolverr), generate retry recommendations:
   ```bash
   analyze-failures -report retry > retry_list.txt
   ```
6. Extract and retry the relevant URLs based on the improvements made
